## 3. Cinco funcionalidades essenciais do MVP

1. **Autenticação e RBAC por perfil.**
2. **Cadastro/vínculo aluno-responsável.**
3. **Registro de entrada e saída por QR/token simulado.**
4. **Notificação automática ao responsável.**
5. **Rastreabilidade por histórico, relatório e auditoria.**

Dashboard, CSV, mensagens, tema, reset e coleta de feedback são recursos complementares de demonstração/validação.

## 5. Normas ABNT - aplicabilidade

A normalização final deve observar a edição vigente adotada pela instituição. Em 2026, referências acadêmicas de bibliotecas universitárias já apontam NBR 14724:2024, NBR 10520:2023 e NBR 6023:2025. Caso a disciplina exija expressamente uma edição antiga, a orientação docente prevalece para a avaliação, mas a divergência deve ser registrada.

| Norma citada no enunciado | Aplicabilidade ao Safe Student |
|---|---|
| NBR 6021 | Indireta; trata publicação periódica como um todo. |
| NBR 6022 | Aplicável ao artigo. |
| NBR 6023 | Aplicável às referências. Usar edição vigente definida pela instituição. |
| NBR 6024 | Aplicável à numeração progressiva. |
| NBR 6027 | Aplicável ao sumário dos trabalhos que o exigem. |
| NBR 6028 | Aplicável ao resumo. |
| NBR 6029 | Não é requisito central; trata livros/folhetos. |
| NBR 6034 | Só é necessária se houver índice. |
| NBR 10520 | Aplicável às citações. |
| NBR 14724 | Aplicável à apresentação do trabalho acadêmico. |
| NBR ISO 2108 | Não aplicável, pois o projeto não solicita ISBN. |
| Norma de Apresentação Tabular - IBGE | Aplicável às tabelas apresentadas. |

## 6. Auditoria técnica do MVP V1.1

### Corrigido nesta revisão

- exportação CSV agora envia o token de autenticação;
- autorização de destinatários de mensagens passou a ser validada no backend;
- cálculo do dia escolar usa fuso configurável (`America/Sao_Paulo` por padrão);
- sessão de apresentação passou de `localStorage` para `sessionStorage`;
- validação de hash foi endurecida;
- cabeçalhos de segurança foram ampliados;
- escrita JSON passou a usar arquivo temporário + `rename`;
- feedback separa dados ilustrativos (`DEMO_SEED`) de evidências realmente coletadas (`APRESENTACAO`);
- suíte ganhou testes de API;
- GitHub Actions executa sintaxe e testes em Node 18, 20 e 22;
- README agora descreve a arquitetura real, separando claramente evolução futura.

### Limitações deliberadas

- persistência JSON local;
- sessões em memória;
- sem HTTPS próprio;
- sem backup/observabilidade corporativa;
- sem serviço real de SMS/push;
- sem biometria/NFC/catracas;
- não é homologação de produção nem certificação LGPD.

## 7. Pendência que não pode ser fabricada

A única pendência acadêmica material que exige ação humana é a **evidência primária da pesquisa/validação com participantes**. O repositório contém instrumentos e resultados agregados declarados, mas não contém respostas anonimizadas, termos preenchidos ou arquivo exportado que permita reproduzir os percentuais. Portanto:

- não inventar participantes;
- não inventar novas respostas;
- manter os resultados antigos identificados como "declarados na versão anterior, pendentes de comprovação";
- utilizar o módulo Feedback V1.1 para registrar novas avaliações reais e exportar `safe-student-validacao-mvp.csv`;
- anexar a exportação e/ou formulários anonimizados ao relatório antes de apresentar os números como evidência verificada.
